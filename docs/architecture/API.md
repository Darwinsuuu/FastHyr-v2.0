# API contract (FastAPI)

Base URL: `https://api.fasthyr.com/v1`. JSON everywhere; errors are `application/problem+json` with a stable `code`. The OpenAPI schema generated by FastAPI is the precise contract; this document is the map. Every endpoint lists its permission (see `SECURITY.md`).

Every path below is under `/v1` (for example `GET /v1/me`); the OpenAPI schema is at `/v1/openapi.json` and `GET /health` stays at the root for the host's health check. Error codes are listed in [`BACKEND.md` §3](BACKEND.md#3-conventions).

Headers: `Authorization: Bearer <supabase access token>` (except public), `X-Workspace-Id` (TA endpoints), `Idempotency-Key` (marked ⚷).

## Public (no auth)
| Method & path | Purpose |
|---|---|
| `GET /public/pipelines/{workspace_slug}/{pipeline_slug}` | Apply page data (APPLY-001): candidate-safe pipeline fields (title, department name, employment type, work setup, location, JD, "Also open to", interview format, open and close dates), `availability` (`accepting` live · `opens_later` scheduled · `not_accepting` paused or out of credits · `closed`), the time zone dates are shown in, and the company profile (name, logo link through the public branding route, website, industry, size, HQ country, about, careers URL). Never must-haves, nice-to-haves, skills to probe, tone, seniority, rubric or credits. Drafts, cancelled pipelines and unknown links are `404` |
| `GET /public/notices` | Current version of every candidate notice (COMP-002): `{apply, interview, biometric}`, each `{id, kind, version, statement, details, links, choices}`. `id` (`<kind>@v<N>`) is what a consent request sends back and the record stores. The page fills `{company}` and each `choices` key (e.g. `{interview}` from the pipeline's interview format) |
| `GET /public/notices/{kind}` · `GET /public/notices/{kind}/{version}` | One notice: the current version, or any released version so a record's consent can be shown word for word. Unknown version `404`; unknown kind `422` |
| `GET /public/branding/{workspace_id}/{logo\|banner}` | Branding image proxy for emails: no sign-in, `Cache-Control: immutable`; links carry `?v=<updated_at>` so a new image gets a new URL (WS-001) |
| `POST /public/contact` | Contact form (rate-limited) |
| `GET /public/review-requests/{token}` · `POST …` `{message?}` | Human-review request page (ADR-015, ASMT-008, S-03). `GET` returns `state` (`open`, `requested`, `expired` past the link's 30 days, `unavailable` once the decision no longer stands or the candidate was deleted), `company` and `job_title` only. `POST` (message up to 1,000 characters) creates the request: Review requested overlay, `review_received` to the candidate, the `review_request` system email to the pipeline owner (the Admins when it has none); a repeat returns `requested`; `409 review_link_closed` when expired or unavailable; unknown tokens `404 review_link_not_found` |
| `POST /demo/sessions` · `POST /demo/sessions/{id}/resume-upload` · `PATCH /demo/sessions/{id}` · `POST /demo/sessions/{id}/realtime` · `POST /demo/sessions/{id}/complete` · `DELETE /demo/sessions/{id}` | Public demo (rate-limited, bot-protected) |

## Me (any signed-in user)
| `GET /me` | profile (id, email, name, avatar, last workspace), verified status |
| `GET /me/workspaces` | active memberships: id, name, slug, role, owner flag, member count |
| `PUT /me/last-workspace` | `{workspace_id}`: remembers the active workspace for the next sign-in on any device (FR-AUTH-04); not a member → 404; 204 |
| `POST /workspaces` | `{name}` (1–120 chars): create workspace; caller becomes owner (Admin); unique slug from the name; company profile stub; trial grant (BILL-002 adds the credits); becomes last workspace; 201 with the `/me/workspaces` row. Verified email only |
| `POST /invites/accept` | `{code}` (bare code in any case, or a pasted `/join/<code>` link) or `{token}` (the link token from the invite email, exact; a pasted `/join/<token>` link also works as `code`): joins with the invite's role and departments, becomes last workspace; returns the `/me/workspaces` row, also if already a member. Errors: `404 invite_not_found`, `403 invite_wrong_email`, `410 invite_expired` / `invite_invalid`. Verified email only (AUTH-003, AUTH-004) |
| `GET /invites/{code}` | join page preview by code or link token (AUTH-004). Verified email only. `{state, workspace_id, workspace_name, invited_by_name, role, departments, masked_email}`; `state` is `ready` (details filled in), `already_member` (`workspace_id` only), `wrong_email` (`masked_email` only, e.g. `d•••@acme.com`), `expired` or `invalid` (nothing else). Unknown is `404 invite_not_found` |

## Candidate (signed-in candidate)
Candidate routes accept only a Google or Microsoft session (ADR-014); any other session is `403 candidate_sign_in_required`. Pipelines are named by ID; drafts, cancelled and unknown ones are `404`.

| `POST /candidate/pipelines/{pipeline_id}/resume-upload` | signed upload URL for the résumé PDF (`{upload_id, url, path, token, max_bytes}`), only while the pipeline is live (`409 pipeline_not_accepting`) (APPLY-003) |
| `POST /candidate/applications` ⚷ | submit application (APPLY-003): `{pipeline_id, upload_id, resume_filename, full_name, phone_country_code, phone, city?, profile_url?, consent_notice_id, source}`; the email is the account's. Checks the résumé (`pdf_*`, `upload_missing`, `upload_expired`) before any credit moves, then uses 1 credit, records the candidate, the application (`processing_resume`), the consent version and time, and queues screening. `201 {application_id, applied_at, created: true}`. Idempotent by candidate and pipeline: applying again returns the first application with `200` and `created: false` and uses nothing (FR-APPLY-05), so no idempotency key is stored. A pipeline that stopped accepting (or lost its last credit to someone else) is `409 pipeline_not_accepting` with no credit used |
| `GET /candidate/pipelines/{pipeline_id}/my-application` | "Applied on…" state: `{applied_at, status, workspace_member}`. `applied_at` and `status` are null when not applied; `status` is `received` (résumé being screened), `interview` (invited or mid-interview) or `with_team` (everything later, decisions included, so the page never gets ahead of the emails). Never a stage, score or flag (FR-APPLY-07). `workspace_member` is true when the account is also an active member of the pipeline's workspace: it may apply, and the form says so (APPLY-004) |
| `GET /candidate/interviews/{token}` | Interview link page (INTV-002, S-01). Sign-in optional: no session, or one that isn't Google or Microsoft, counts as signed out (a token that fails its check is still `401`). `state` in check order: `unavailable` (replaced link, cancelled pipeline, rejected application, deleted candidate) · `expired` · `sign_in` · `wrong_account` · `completed` (interview done or application past it; never turns expired or unavailable later) · `technical_problem` (`drop_reason = technical_issue`) · `resume` · `welcome`. Also `company {name, logo_url, website, careers_url}`, `job_title`, `format`, `expires_at`, `expires_label` (the invitation email's wording), `first_name` (only for the applying account), `masked_email` (only on `sign_in`), `minutes_left` (only on `resume`). Looked up by the token's SHA-256; unknown tokens `404 interview_not_found` `face_check` says whether the device check asks for the biometric consent (INTV-003). |
| `POST /candidate/interviews/{token}/consent` ⚷ | Device check consent (INTV-003, FR-INTV-03): `{consent_notice_id, biometric_notice_id?}` from `GET /public/notices`; the biometric id is required when the link's `face_check` is true (video + "Flag possible impersonation"; `422 biometric_consent_required`) and ignored otherwise. Stores `consent_version`, `consent_at`, `biometric_consent_version` on the interview; agreeing again keeps the latest. Another account or an unknown token `404 interview_not_found`; an expired, closed or finished link `409 interview_not_open`; `409 notice_outdated` / `422 notice_unknown` as for apply. `200 {consent_version, consent_at, biometric_consent_version}` |
| `POST /candidate/interviews/{token}/session` | Start or resume the live interview (INTV-004, ADR-021): `{sdp}` (the browser's WebRTC offer). The API opens the OpenAI Realtime call with it and the interviewer's instructions, ends any running attempt, and queues the sideband job. `200 {attempt_id, sdp (OpenAI's answer), time_left_seconds, wrap_up_in_seconds, heartbeat_seconds, topics[{number, title}], topic_number}`. Another account or an unknown token `404 interview_not_found`; no consent yet `409 interview_consent_required`; an expired, closed or finished link (or no time left) `409 interview_not_open`; three connections that never came up within 5 minutes `409 interview_technical_issue` (the link page then shows `technical_problem`); OpenAI down `503 realtime_unavailable`; offer refused `422 realtime_offer_rejected`. Recording upload URLs come from `…/chunk-urls` (INTV-006) |
| `POST /candidate/interviews/{token}/chunk-urls` | Recording uploads (INTV-006): `{attempt_id, type: webm|mp4, from_seq, count (1–30)}` → `200 {urls[{seq, url}]}`, signed upload URLs to PUT each chunk to once. The first request fixes the attempt's type (`409 recording_type_mismatch` for another). Works after the interview finished or the link expired, while the last chunks arrive; a withdrawn link `409 interview_not_open`; another account `404 interview_not_found`; an attempt of another interview `404 interview_attempt_not_found`; once finalising began `409 recording_finalized` |
| `POST /candidate/interviews/{token}/chunks` | Registers an uploaded chunk: `{attempt_id, seq, last}` (`last` = the attempt's recorder stopped; nothing follows). Checked in Storage: not there `422 recording_chunk_missing`, over 50 MB `422 recording_chunk_too_large` (deleted). Repeating it is fine. The last chunk of a completed interview queues `finalize_recording`. `200 {seq, bytes}`; same `404`/`409` as above |
| `POST /candidate/interviews/{token}/heartbeat` | Every 15 s: `{attempt_id, connected}`. Counts talk time on the server's clock and records the connection (clearing a `technical_issue`). `200 {status: active|wrap_up|ended, time_left_seconds, end_reason}`; `ended` once the attempt is over (time up, interviewer or candidate ended it, a newer attempt began, or the watchdog ended it). Unknown attempt `404 interview_attempt_not_found` |
| `POST /candidate/interviews/{token}/complete` | The candidate ends the interview: `{attempt_id?}`. Ends the running attempt (`candidate_ended`), hangs up, sets the interview `completed` and the application `scoring`. Repeating it returns `200` again; before any attempt `409 interview_not_open`. `200 {status: completed, talk_seconds}` |
| `POST /candidate/interviews/{token}/feedback` | 1–5 rating + comment |

## Workspace (TA) — all require membership via `X-Workspace-Id`
### Workspace admin
| `GET/PUT /workspace/company-profile` · `POST …/branding-upload` | Admin. GET adds 15-min signed `logo_url`/`banner_url`. PUT saves the whole form (`company_name` required; website and careers page as http(s) URLs, a bare host gets `https://`; `industry`, `company_size` as fixed keys; `hq_country` ISO alpha-2; `timezone` IANA, also copied to `workspaces.timezone`; `about` ≤ 600) plus `logo_upload_id`/`banner_upload_id` or `remove_logo`/`remove_banner`. Image errors: `image_invalid`, `image_too_large`, `image_too_big`, `logo_not_square`, `logo_too_small`, `upload_missing`, `upload_expired`. `branding-upload {kind}` returns a signed upload URL (10-min window) |
| `GET/POST /departments` · `PATCH/DELETE /departments/{id}` | read: member · write: Admin. `GET` returns `{departments, no_department}`; each department has `assigned` (true for every department for Admins, else only the member's own; the wizard files pipelines only under these, PIPE-002); Admins also get each department's `stats` (pipelines by active/scheduled/closed/draft, candidate count, members who can see it) and `no_department` stats. Names 1–40 chars, unique ignoring case (`409 department_name_taken`), "No department" reserved (`422 department_name_reserved`). `DELETE` moves pipelines to No department (WS-002) |
| `GET /members` · `PATCH /members/{id}` · `DELETE /members/{id}` | Admin. `GET` returns `{members}`: every active member (owner first, then by name) with name, email, avatar, role, owner and `is_you` flags, departments (empty for Admins, who see all), `last_active_at`. `PATCH {role?, department_ids?}` (making someone Admin clears departments; unknown departments `422 unknown_department`); `DELETE` sets status `removed` (an invite brings them back). The owner can't be changed or removed (`409 owner_access_locked`), nor can your own access (`409 own_access_locked`). Changes apply on the member's next request (WS-003) |
| `GET/POST /invites` · `POST /invites/{id}/resend` · `DELETE /invites/{id}` | Admin. `GET` returns `{invites}`: pending invites that haven't expired, most recently sent first, with email, role, departments, `code`, inviter name, `sent_at`, `expires_at`. `POST {email, role, department_ids}` (`201`) invites for 7 days and replaces any pending invite for that email; Admins get no departments; unknown departments `422 unknown_department`; someone with access already `409 already_a_member`. `resend` gives a new code and token and a fresh 7-day expiry (the old link and code stop working); `DELETE` revokes (`204`). Accepted, revoked and expired invites are `404` to both (WS-004) |

### Dashboard & analytics
| `GET /getting-started` | checklist state |
| `GET /analytics/overview?range=week\|30d` | `VIEW_OVERVIEW` (DASH-003). `week` = the last 7 days, `30d` = the last 30, each against the period before; days, weeks and months in the workspace time zone (`timezone`). Returns `period`, `shortlist_only`, `kpis` (applicants and change %, still processing, ready for review, flagged, advanced, live/paused/scheduled pipelines, median days from applying to a finished interview and its change), `attention` (ready-for-review queue, flagged, pipelines paused for credits or running low with days of credits at the last 14 days' pace, plan credits expiring within 7 days, invites expiring within 3 days; review requests come with ASMT-008), `funnel`, `top_candidates` (5 waiting longest-scored first), `closing_soon`, `weekly` (8 weeks applied/passed), `sources` (pass rate), `dropoffs` (last 30 days) and `credits`. Department-scoped; Hiring managers get shortlist numbers only and `null` for applicants, funnel, weekly, sources, drop-offs and credits |
| `GET /analytics/pipelines-flow?range=week\|30d` | `VIEW_PIPELINES`. The Pipelines page band (FR-PIPE-08): applications to open pipelines (live, paused, out of credits) that applied in the range and where they are now: `applied` and `applied_change_pct`, `processing`, `invited`, `not_a_match`, `interviewed`, `in_progress`, `not_started`, `scoring`, `ready_for_review` (no open flags), `flagged`, `did_not_pass`, and `median_hours_to_assessment` for assessments made in the range |

### Pipelines
| `GET /pipelines?tab=&q=&page=&page_size=` | The Pipelines list (PIPE-004, FR-PIPE-08), scoped to the caller's departments (Admins: all). `tab`: `live` (live, paused, out of credits), `scheduled`, `closed` (closed, cancelled), `drafts` or `all`; archived pipelines never show. `q` matches title or department name (literal text). `page_size` 1–25. Sorted needing attention first: out of credits, open with candidates to review (most first), other open (closing soonest), scheduled (opening soonest), drafts (edited last), ended (ended last). Returns `{items, total, page, page_size, counts: {live, scheduled, closed, drafts, all}, to_review, timezone}`; each item has status, `closed_reason`, title, slug, department, owner (name, email, avatar), `candidates`, `to_review` (ready for review and not flagged), `credits_used`, `credits_reserved` (a draft's planned reserve), `opens_at`, `closes_at`, `ended_at`. `counts` ignore the search |
| `POST /pipelines` · `GET/PATCH /pipelines/{id}` | draft create/edit (PIPE-001). Every setup field is optional so a draft saves at any step; PATCH changes only the fields sent and works on drafts and on scheduled pipelines until they open (not their `open_mode` or `credits_to_reserve`). Opened pipelines: `409 pipeline_locked`. `GET` also returns `department` (`{id, name}`, null for No department) and `owner` (name, email, avatar; null once they've left) for the details header (PIPE-007). A Recruiter's pipeline must be in one of their departments (`422 unknown_department`); weights that are all set must total 100 (`422 pipeline_incomplete`) |
| `POST /pipelines/{id}/publish` | `{confirm: "I understand"}` → live (`open_mode: now`) or scheduled. Reserves `credits_to_reserve` (min 10, steps of 10; `409 insufficient_free_credits`) and fixes the slug. `422 pipeline_incomplete` lists the missing fields in `errors[].loc` |
| `POST /pipelines/{id}/start-now` · `/pause` · `/resume` · `/close` `{notify}` · `/cancel` · `/archive` · `/duplicate` | lifecycle (PIPE-001, PIPE-005). `/close` takes an optional `{notify: bool}` (default false): with it, every application that hasn't heard back (see NOTIFICATIONS.md, `role_closed`) gets the "Role closed" email at once, and the response adds `notified` (how many); stages don't change. An action the status doesn't allow is `409 invalid_transition` (WORKFLOW.md §2). Going live with no reserve or workspace credits left lands in `paused_no_credits`. `/duplicate` returns the new draft (201) |
| `POST /pipelines/{id}/top-up` ⚷ `{credits: 25\|50\|100\|200}` | reserve more from free credits; a pipeline paused for credits goes back to live |
| `GET /pipelines/{id}/share-links` | tagged URLs per source |
| `GET /pipelines/{id}/dashboard` | Viewer, in the caller's departments (else `404`). `kpis` (candidates, new this week, ready for review, median days to assessment, credits used/reserved, days remaining, `closes_at`), `funnel` (applied, invited, interviewed, ready for review, flagged), `daily` (last 14 days), `scores` (10-point bins, 90 holds 90 to 100) with `pass_mark`, `interviewed`, `passed`, `sources` (résumé pass rate) and `dropoffs` (by reason, `invited`, and `reinvitable` for "Re-invite all") (DASH-003) |
| `POST /pipelines/{id}/reinvite` `{scope: "all_unfinished"}` | Recruiter (own departments) / Admin. "Re-invite all" (INTV-007): a new link and invitation for every application in `invited`/`interview_in_progress` whose live interview expired, was left unfinished, or hit a technical issue; candidates in a running attempt are skipped. Cancelled or archived pipeline: `409 reinvite_not_allowed`. `200 {reinvited}` |

### Applications & candidates
| `GET /pipelines/{id}/applications?stage=&q=&page=&page_size=` | `VIEW_CANDIDATES`, pipeline in the caller's departments (else `404`). The Candidates tab (PIPE-008, FR-PIPE-12). `stage`: `all`, `processing`, `not_a_match`, `invited`, `in_progress` (interview in progress or scoring), `ready` and `did_not_pass` (without open flags), `flagged` (open flags on a ready or did-not-pass application), `review_requested` (overlay), `advanced`, `rejected`. `q` matches the candidate's name or email (literal text). `page_size` 1–50 (the tab offers 10, 25, 50). Sorted ready, flagged, in progress, scoring, invited, processing, advanced, didn't pass, not a match, rejected, then score (high first) and newest. Returns `{items, total, page, page_size, counts, shortlist_only, pass_mark, timezone}`; `counts` has every filter before the search; each item has the application id, candidate (id, name, email), stage, `flagged`, `review_requested`, `fit`, `overall_score`, `must_haves` (met of total on the résumé screen), `strongest` interview criterion, open `flag_types`, source and `applied_at`. Hiring managers get shortlisted applications only (ready for review, flagged, advanced) and `shortlist_only: true` |
| `GET /applications/{id}` | `VIEW_CANDIDATES` (ASMT-004, FR-ASMT-07). The candidate profile. Pipeline outside the caller's departments, another workspace, or (Hiring managers) an application outside the shortlist: `404`. Returns the application (`stage`, `flagged`, `open_flags`, `review_requested`, `fit`, `source`, `applied_at`), `candidate` (id, name, email), `pipeline` (id, title, status, pass mark, format, integrity on/off, `rubric_locked_at`), `workspace_name`, `timezone`; `resume` (status, fit score, pass bar, passed, must-haves met, screened time); `interview` (latest: status, format, times, length, `recording_ready`, assessment and integrity status); `assessment` (latest, or null: overall, passed, fit, `pass_mark` it was scored against, each criterion's score, weight, points, signals, evidence (`source` interview or résumé, quote, `start_ms` on the recording's clock, label) and what held it back, topics with the pipeline's average for matching topics, summary with numbered refs, strengths, probes, `answer_stats`, `evidence_count`, `assessed_at`); `comparison` among every assessed interview in the pipeline (aggregates only, the same for every caller: `interviewed`, `rank` (ties share), `average`, `passed`, `distribution` by `start` 0/50/60/70/80/90, per-criterion `average` and `passed_average`, answer-pattern averages); `integrity` (status, which checks ran, flags with type, times, `confidence`, status); `history` (the person's applications here the caller can see) and `journey` (applied → résumé → invited → finished → assessed → advanced/rejected, with times) |
| `GET /applications/{id}/transcript?q=` | transcript segments (search) |
| `GET /applications/{id}/recording-url` | Same access as the profile (ASMT-004). Signed links (15 minutes) to the latest interview's finished recording and, for video, its poster: `{url, poster_url, kind: video\|audio, duration_seconds, expires_at}`. No finished recording (or its file is missing): `404 recording_not_ready` |
| `GET /applications/{id}/resume-url` | signed URL |
| `POST /applications/{id}/advance` `{note?, send_email}` | `DECIDE_CANDIDATES`: Admins, Recruiters in their departments; Hiring managers `403` (ASMT-007, ADR-017). From `ready_for_review` only; open integrity flags: `409 flags_to_review`; any other stage (advanced and rejected are final): `409 decision_not_allowed`. `note` up to 1,000 characters (team only). Sets `advanced_note`/`advanced_by` (member)/`advanced_at`, moves the stage (waiting emails cancelled) and, unless `send_email` is false, sends `next_stage` now. Audited as `application.advanced` (from, emailed; never the note). Another workspace, a pipeline outside the caller's departments or deleted candidate data: `404`. `200 {id, stage, emailed}`; the profile's journey step carries `by` and `note` |
| `POST /applications/{id}/reject` `{reason, send_email}` | Same access (ASMT-007, FR-PIPE-13). From `invited`, `interview_in_progress`, `ready_for_review` (flagged or not) or `processing_resume` with an unreadable résumé; else `409 decision_not_allowed`. `reason` 1–500 characters, required (team only). A running interview attempt ends and its call is hung up; the link reads `unavailable`. Waiting emails are cancelled and, unless `send_email` is false, the rejection goes now: `reject_interview` after a finished interview, otherwise `reject_resume`, with `[Review.link]` (a `review_links` row of that decision type, 30 days). Audited as `application.rejected` (from, emailed; never the reason). `200 {id, stage, emailed}` |
| `POST /applications/{id}/invite-manually` | for unreadable résumés or overrides |
| `POST /applications/{id}/reinvite` | Recruiter (own departments) / Admin. New interview link (new token, fresh expiry, full 30 minutes, same plan and credit); the old link reads `unavailable`; stage back to `invited`; waiting emails of the old link cancelled; invitation (and reminder) sent; audit `application.reinvited` (INTV-007). Finished or running interview, other stages, or a cancelled/archived pipeline: `409 reinvite_not_allowed`. `200 {reinvited: 1}` |
| `PATCH /integrity-flags/{id}` `{status, note}` | `RESOLVE_REVIEWS`: Admins, Recruiters in their departments (ASMT-003, FR-ASMT-06). `status` `no_concern` or `concern_confirmed`; `note` up to 1,000 characters, required for a confirmed concern (`422`). Sets who and when; a reviewed flag can be reviewed again but never reopens. The stage never changes; when the application's last open flag is reviewed, `has_open_flags` clears and it leaves the Flagged filter. Audited as `integrity_flag.resolved` (application, type, from, to; never the note). Another workspace, a pipeline outside the caller's departments or deleted candidate data: `404`. Returns `{flag, application: {id, flagged, open_flags}}`; the profile's flags carry `resolved_at`, `resolved_by` (name) and `note` |
| `GET /review-requests?status=open\|upheld\|overridden\|all` · `POST /review-requests/{id}/resolve` `{outcome: uphold\|override, note}` | `RESOLVE_REVIEWS` (Admins; Recruiters in their departments; else `404`), ASMT-008. The list is oldest first (100 at most) with `total`. Resolve needs a note (1–1,000 characters, the team's only). Uphold: no email. Override: a résumé decision in `resume_not_match` → `invited` with the fallback skills plan when there is none, a new interview link and the invitation; an interview decision in `did_not_pass` → `ready_for_review`, no email. A person's own rejection (`rejected`) can be overridden the same way, by the link's decision type (for a résumé link a new interview link replaces the closed one, as a re-invite does); `409 override_not_allowed` once the decision no longer stands, or to invite on a cancelled or archived pipeline; `409 review_request_resolved` once resolved. Audited `review_request.resolved` without the note |
| `GET /candidates?filter=&q=&page=` · `GET /candidates/{id}` | pool (read-only) |
| `GET /candidates/dashboard` | `VIEW_CANDIDATE_POOL` (DASH-003): `kpis` (people, new this month, applied more than once, interviewed and across how many pipelines, passed, median days to assessment), `new_per_month` (6 months), `repeats` (once, twice, three times, four or more, pass rates of returning and first-time people), `stages` (applications per stage, every stage present) and `sources` (people by first source). Department-scoped; Hiring managers count shortlisted applications only (`shortlist_only`) |
| `POST /candidates/{id}/delete` | Admin — data deletion (FR-COMP-05) |

### Jobs
| `POST /reports` `{kind, params}` · `GET /jobs/{id}` · `DELETE /jobs/{id}` · `GET /jobs/{id}/download-url` | PDF generation with progress |
| `GET /jobs/{id}` | any member, own jobs only (anyone else gets 404): `{id, kind, status, step, steps_total, error, created_at, finished_at}`; `error` is a stable code. Poll until `status` is `done`, `failed` or `cancelled` (FND-008) |
| `DELETE /jobs/{id}` | cancel a queued or running job (the worker stops before its next step); a finished job stays as it is; 204 (FND-008) |
